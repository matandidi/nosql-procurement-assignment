# מערכת לניהול צורך, מלאי והזמנות של פריטים מוגבלי חיי מדף

עבודת הסיכום של מתנאל דידי בקורס NoSQL. המימוש ב-MongoDB עונה על שלוש שאלות: באילו פריטים צפוי חוסר ובאיזו שנה, אילו שורות הזמנה צפויות לאחר למועד הצורך, ואצל אילו ספקים מרוכזת הכמות המאוחרת.

[פתיחת האפליקציה](https://nosql-procurement-matan.netlify.app)

כל הפריטים, הספקים וההזמנות הם נתוני דוגמה פיקטיביים. המסמך והמצגת מוגשים בנפרד ואינם כלולים במאגר.

## מבנה המודל

הנתונים מחולקים לשלושה אוספים:

- `items` — פרטי הפריט, אצוות המלאי והצרכים לשנים 2027–2029. האצוות והצרכים שמורים בתוך הפריט, כי חישוב החוסר משתמש בהם יחד.
- `purchase_orders` — הזמנה עם מערך שורות. בכל שורה מופיעים מזהה הפריט, שנת הצורך והכמות שכבר סופקה. ההזמנות נפרדות מהפריטים כדי לשמור הזמנה אחת גם כשהיא כוללת כמה פריטים.
- `suppliers` — פרטי הספק. ההזמנה מפנה אליו באמצעות `supplier_id`.

ההפרדה מאפשרת להציג שורות הזמנה, אך לספור הזמנה אחת בלבד בסיכום לפי ספק. בשאלה 3 הספירה נעשית באמצעות `$addToSet` על מספר ההזמנה.

## איך לקרוא את התוצאות

**שאלה 1 — חוסר:** הצורך המצטבר עד השנה הנבדקת, פחות מלאי פתיחה תקף ופחות יתרות הזמנה שיגיעו עד מועד הצורך. לדוגמה, ל-ITM003 בשנת 2027 נדרשות 60 יחידות, המלאי התקף הוא 40 ואין אספקה שתגיע בזמן. החוסר הוא 20.

**שאלה 2 — איחור:** יתרת הכמות בשורה שתגיע אחרי מועד הצורך. התוצאה הכוללת היא 510 יחידות מאחרות, ולא 510 יחידות חסרות. ל-ITM004, למשל, יש מלאי תקף של 55 מול צורך של 45 בשנת 2027. ההזמנה שלו מאחרת, אך המלאי מספיק.

**שאלה 3 — ריכוז לפי ספק:** סכימת היתרות המאחרות בכל ספק. התוצאה היא 280 יחידות אצל SUP004 ו-230 אצל SUP002. זהו דירוג לפי כמות בנתוני הדוגמה; הוא לא משווה את שיעור האיחור מתוך כלל ההזמנות של כל ספק.

יש למודל כמה הנחות שכדאי להכיר:

- `safety_stock` מצטרף לצורך בכל שנה. הוא אינו יתרת מינימום קבועה שנשמרת במלאי.
- המלאי נבדק מול תאריך הצורך. אין במימוש הקצאת אצוות לצריכה לפי FEFO, ובנתוני הדוגמה אין אצווה שפוקעת במהלך 2027–2029.
- תוקף של אספקות עתידיות אינו מחושב. הכמויות שכבר סופקו מופחתות מיתרת ההזמנה, כדי שלא להוסיף אותן שוב למלאי הפתיחה.

## הקמה והרצה ב-mongosh

נדרשים MongoDB מקומי או Atlas, התקנת `mongosh` ומשתמש עם הרשאת `readWrite` למסד `nosql_procurement_assignment`. בחיבור ל-Atlas צריך לאפשר את כתובת ה-IP של המחשב ב-IP Access List.

**סקריפט ההקמה מוחק ומחליף את `items`, `purchase_orders` ו-`suppliers` במסד הזה.** יש להריץ אותו רק כשמעוניינים לאפס את נתוני הדוגמה.

מתוך תיקיית המאגר מתחברים כך. הסיסמה מוזנת בבקשה של mongosh, ולא בתוך הקבצים:

```bash
export MONGODB_URI='mongodb+srv://YOUR_CLUSTER_HOST/'
export MONGODB_USER='YOUR_DATABASE_USER'
mongosh "$MONGODB_URI" --apiVersion 1 --username "$MONGODB_USER"
```

אחרי החיבור:

```javascript
load('mongodb/01-create-and-seed.js')
load('mongodb/03-validation-queries.js')
load('mongodb/02-research-queries.js')
```

בסיום ההקמה אמורים להופיע `SEED COMPLETED` וספירות של 8 פריטים, 4 ספקים ו-8 הזמנות. בדיקה תקינה מסתיימת ב-`VALIDATION PASSED`.

להרצה דרך הממשק של Atlas, הוראות וקובצי JSON נמצאים ב-[mongodb/atlas](mongodb/atlas/README.md). נדרשת טעינה של נתוני הדוגמה לפני הרצת השאילתות.

## האפליקציה

הדפדפן מציג את התוצאות; החישוב מתבצע ב-MongoDB Atlas דרך Netlify Function. הכפתור „הצג pipeline” מציג את השאילתה שנשלחה למסד. הממשק כתוב ב-HTML, CSS ו-JavaScript, ללא ספריית ממשק או שלב build.

הגדרות הפריסה נמצאות ב-`app/netlify.toml`. ב-Netlify מוגדר Base directory בשם `app`, ומשתנה הסביבה `MONGODB_URI` מכיל את החיבור עם הרשאת `read` בלבד למסד העבודה. פרטי החיבור נשארים בצד השרת.

`questions.json` מכיל את הכותרות, העמודות ועותק של כל pipeline עבור האפליקציה. כשמשנים שאילתה ב-`mongodb/pipelines.js`, צריך לעדכן גם את העותק הזה ואת קובץ ה-JSON המתאים ב-`mongodb/atlas/`. הבדיקות מזהות חוסר התאמה ביניהם.

## בדיקות

בדיקות הקוד המקומיות רצות ב-Node.js 18 ומעלה, ללא חיבור למסד וללא סיסמה:

```bash
cd app
npm test
```

הן בודקות בקשות לא תקינות, שימוש חוזר בחיבור, התאוששות מניסיון חיבור שנכשל, ואת ההתאמה בין עותקי השאילתות. לאימות מול MongoDB עצמו משתמשים ב-`03-validation-queries.js` לאחר טעינת הנתונים.

בהרצות המתועדות מ-1.9.2026 ומ-3.9.2026 על MongoDB Atlas התקבלו 12 תוצאות לשאלה 1, 8 שורות ובהן 510 יחידות לשאלה 2, ו-280/230 יחידות לשאלה 3. בדיקות השלמות הסתיימו ב-`VALIDATION PASSED`. צילומי ההרצה נמצאים בתיקיית `screenshots/`, ובפרט בצילומים 07–11.
